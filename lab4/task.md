# Задание:

**ФИИТ 2025-2026 учебный год, весна**
**Лабораторная работа №4. Исследование индексирования и оптимизации запросов в PostgreSQL**

**1. Цель работы**

Провести экспериментальное исследование эффективности индексирования в PostgreSQL и обосновать выбор оптимальных индексов для различных типов запросов на основе анализа планов выполнения и характеристик данных.

**2. Общие требования**

В рамках лабораторной работы студент должен:
- использовать собственную схему базы данных, состоящую минимум из трёх связанных таблиц;
- обеспечить достаточный объем данных для анализа (не менее 1 000 000 строк в таблице, которая планируется к индексированию);
- самостоятельно определить и реализовать стратегии индексирования;
- обосновать выбор индексов на основе:
  - типа данных;
  - характера операций в запросе;
  - распределения значений (селективности);
  - структуры запроса.

Типы индексов заранее не задаются и должны быть выбраны студентом самостоятельно.

**3. Методика выполнения**

Для каждого исследуемого запроса необходимо:
1. Выполнить запрос без дополнительных индексов;
2. Получить план выполнения с использованием EXPLAIN ANALYZE;
3. Проанализировать узкие места выполнения;
4. Сформулировать гипотезу об оптимизации запроса;
5. Создать индекс (или несколько) по собственному выбору;
6. Повторно выполнить запрос;
7. Сравнить результаты (план выполнения и время);
8. Сделать вывод о корректности гипотезы.

**4. Набор исследуемых сценариев**

В работе должно быть рассмотрено 6 различных запросов, каждый из которых отражает отдельный тип задачи.

Требования к запросам:
1. **Сложный фильтр.** Запрос с несколькими условиями (включая точное сравнение и диапазон).
2. **Сортировка с ограничением.** Запрос с ORDER BY и LIMIT.
3. **Альтернативные варианты индексирования.** Запрос, для которого возможно предложить как минимум два различных варианта индекса, подлежащих сравнению.
4. **Текстовый поиск.** Запрос с поиском по текстовому полю (подстрока, префикс и суффикс).
5. **Соединение таблиц (JOIN).** Запрос, включающий соединение двух или более таблиц.
6. **Негативный сценарий.** Запрос, для которого индекс:
   - не используется, или
   - не даёт значимого прироста производительности.

Для каждого запроса необходимо провести полный цикл анализа, описанный в разделе 3.

**5. Дополнительное требование**

Отдельно необходимо исследовать влияние индексов на операции изменения данных. Сравнить производительность операций INSERT/UPDATE:
- без дополнительных индексов;
- при наличии индексов.

Результаты должны быть зафиксированы и проанализированы.

**6. Требования к результатам**

Для каждого из 6 запросов в отчёте должны быть представлены:
- текст SQL-запроса;
- сформулированная гипотеза;
- описание созданного индекса (или индексов);
- план выполнения до оптимизации (EXPLAIN ANALYZE);
- план выполнения после оптимизации;
- сравнение времени выполнения;
- анализ изменений в плане выполнения;
- обоснованный вывод.

Формат отчета — свободный, который позволит проверить результаты экспериментов.
